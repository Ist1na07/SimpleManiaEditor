# 0.1.17：恢复校验、启动布局与播放连贯性

- 修复普通谱面 checkpoint 写入新缓存后未同步更新 WorkingSha256 的问题。这会在正常退出后把编辑器自己的缓存误判为被修改，与官方 Songs 编辑并无必然关系。当前只读检查中 FEHLT 的源谱校验一致、缓存校验不一致，与此缺陷相符。
- 新版自动保存、退出持久化及恢复清单同步记录实际写入的缓存指纹。旧版不一致但可解析的脏副本保留为需要核对的恢复版本，不用源谱覆盖它；核对后另存为不同文件再继续。此状态跨重启保存，不重复误报，也不允许直接覆盖旧源文件。不可解析/无可信校验的缓存需要回退时，先保留 `Editing Cache/desktop-workspace/unverified/*.mc` 副本（关闭标签或正常清理不会删除）。恢复提示把原因放在路径之前，长文件名不再遮住说明。
- 底板的期望平移独立于暂未完成的 ScrollViewer 尺寸计算，待实际内容布局完成后再应用。启动时主轨靠近左侧全局栏；改变窗口尺寸、增删附加轨不再因临时尺寸强制归零而露出大片空白。仍可手动把全部轨道拖出视野。
- 顶部新增「显示 / 布局」：随时恢复/隐藏全局密度、全局难度；「整理布局：主轨归位」把主轨放回首位、清除底板平移并归位右下角调整卡片。原右侧设置入口也保留，显示偏好持久化。
- 播放中完整 UI 刷新不再把轨道写回约 50 ms 前的导航位置。展示位置使用合成帧时间、独立视觉时钟和受限的音频时钟漂移校正，吸收离散音频采样的停走变化；定位、暂停、切换倍率会重新锚定。所有同步轨跟随同一展示位置，打击音调度和真实音频时钟不受视觉平滑影响。

验证：52 项核心规格，完整编辑器/皮肤/音频回归；普通脏 checkpoint 正常重启、旧版恢复保护和另存为、损坏缓存保留、初始底板位置、延迟布局/缩放/归位、全局栏恢复、播放中 UI 刷新不回跳，以及 0.5x/1x/2x 离散音频采样下的显示步长和漂移边界。实际屏幕与音频设备上的流畅度仍需真实体验确认。
