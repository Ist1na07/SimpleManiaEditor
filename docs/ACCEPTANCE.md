# 验收与测试计划

本文是待实施的验证规范，不是已通过的测试报告。对应阶段见 [完整规划](PLAN.md)。

路线更新：当前采用 Luma 的 C#/.NET + Avalonia，具体阶段与已执行审计测试见 [改造方案](LUMA_ADOPTION.md)。本文的资料保留、回放、恢复、性能和真实环境要求继续适用；Python/TypeScript 跨语言验证改为统一 C# 内核及协议的一致性验证，浏览器专项改为 Avalonia 输入/渲染和原生音频验证。原有浏览器指标保留作原方案参考，不作为当前客户端已完成项。

## 1. 验证职责和交付规则

Codex 完成自动化、静态检查、构建、浏览器验证、故障注入与测试记录；用户验收真实 osu! 行为、音频设备、操作手感和功能取舍。

每次交付包含可启动版本、样本项目、通过/失败记录、已知限制及简短的用户测试步骤。不能把“自动测试通过”描述为所有真实环境兼容。

严重数据损坏、静默覆盖、撤销错误、导出丢音符属于停止发布的问题。新功能依赖未通过时，不通过增加 UI 掩盖基础问题。

## 2. 核心语义测试

| 范围 | 关键用例 | 成功条件 |
| --- | --- | --- |
| `.osu` 往返 | Unicode/空字段、CRLF/LF、未知字段/section、样本引用、异常对象、不同格式版本 | 未编辑文件尽量字节保持；编辑后未涉及内容保持；语义与预期差异一致 |
| `.osu` 兼容 | 自制合法图、tap/LN、红绿线、背景/视频/break、sample/故事板资料 | 通过固定官方解析器；真实客户端能打开并表现一致；保留与支持编辑分别记录 |
| 时间模型 | 1/3、1/7 网格、小数 BPM/offset、负 offset、多段 BPM、同刻红绿线 | 统一舍入，无累积漂移；Python/TS 对相同向量输出相同时间 |
| 选择/命中 | LN 头在窗口外、长 LN、缩放/滚动、多列、重叠对象 | 与指定选择规则一致；可见 LN 不漏选、不漏绘 |
| 命令回放 | 不同操作序列、批量粘贴、中心对称、跨轨道/文档 | 从基线回放等于直接编辑的规范化状态/hash |
| 撤销/重做 | 添加/删除/移动/LN/timing/声音/轨道/元数据、合并手势 | apply→undo 恢复旧状态；redo 恢复新状态；新编辑与历史浏览语义正确 |
| 命令传输 | 重复 opId、乱序、拒绝、断线重发、旧 revision | 不重复放键；冲突明确；客户端与已确认服务状态最终一致 |
| 批事务 | 上千对象、跨文档、部分校验失败 | 整体提交或整体失败，没有半段粘贴 |
| 变换工具 | 列循环/时间平移/左右镜像/时间反转/中心对称、中央列 | 逆变换及对称两次恢复原状态；边界和去重遵循规则 |
| LN 与声音 | 头尾变化、面转米、同列冲突、继承/自定义样本 | 不产生意外负长 LN；声音绑定和导出行为符合指定策略 |
| Pattern | 分数拍、跨 BPM 粘贴、列映射、文本复制/导入 | 文本往返保持结构；预览等于提交结果；未共享声音明确提示 |
| 多模式 | 完整/最小/RC 切换、快捷键禁用、已有 LN/SV/声音 | 切换不删数据；所有输入入口遵守相同能力约束 |

使用跨语言固定向量和性质测试验证核心不变量；不只写“调用方法后 equals 实现常量”的测试。官方格式和难度通过固定来源 oracle 验证，不能仅依赖自己的 parser 相互印证。

测试样本包含 7K 为主，另有 4K 与非典型列数检查模型是否写死。所有会持久化的核心命令必须有有效回放、反向操作、边界/无效输入与协议版本用例。

## 3. 数据与故障注入

自动化在临时目录/文件副本中运行，每项检查源、目标、日志、快照和恢复后的 revision：

1. 在日志追加中途、flush 前后、快照生成/替换中途强制终止进程；恢复不得回放半条操作。
2. 在 `.osu` 临时文件写入、解析验证、替换和多文件保存中途终止；应保有旧有效版本或完整新版本，并能处理事务清单。
3. 截断日志、修改校验值、损坏快照；隔离损坏资料，使用最近的有效基线并给出可定位说明。
4. 模拟磁盘满、无写权限、文件占用、目录掉线、重命名及路径过长；不能显示虚假的已保存。
5. 前端关 tab、浏览器崩溃、服务断开并重启；区分已持久化与待确认记录，重发不能重复。
6. 同文档被两个窗口打开，或 osu! 在外部修改源文件；禁止静默最后写入覆盖。
7. 跨盘迁移中途终止、校验失败、源文件变化、目标同名、公共资源仍被源难度使用；源资料不能过早删除。
8. 旧格式升级中途失败与新版格式被旧版打开；原始项目可恢复，未知内容不静默丢弃。
9. 清除/重建 SQLite、清除所有缓存、移动创作目录；项目、标签、备注、命名版本仍存在且能重新关联。
10. 快照压缩与历史清理后，仍被版本引用的歌曲/声音资源保持可用；恢复旧版本不改变新版本。
11. `.osz` 路径穿越和损坏归档、非法根路径/符号链接越界、外站 Origin/未授权 WS；文件接口按配置边界拒绝请求。

强制进程终止可重复测试，但不能完全模拟电源故障或所有硬盘行为。发布说明准确说明持久化确认、未确认窗口和备份能力。

## 4. 浏览器、音频与试玩测试

| 项目 | 自动化验证 | 用户真实环境验证 |
| --- | --- | --- |
| 音频时钟 | 合成 click track、输出时间映射、速率切换和 seek 后连续性 | 听觉/录音确认显示、节拍器和音乐对齐 |
| 保音高 | 对已知频率正弦/和弦测时长与主频，覆盖所有默认倍率 | 不同歌曲的失真、瞬态、0.1x 可用性与质量档 |
| 变调 | 联动变调及独立半音参数、速度与 pitch 分离 | 听感和播放偏好 |
| 循环/seek | 无旧音频残留、循环边界、快速重复跳转、暂停恢复 | 大文件、压缩音频、频繁试听的手感 |
| hitsound | 预调度事件、继承解析、样本混音、LN 生命周期 | 与指定 stable/lazer 版本在相同样本下对照 |
| 试玩输入 | 注入带时间戳的事件、OD 边界、LN 提前松手、同刻多键、自动重复键 | 键盘 rollover、输入法/布局、7K 实际键位 |
| 试玩倍率 | 歌曲位置与判定窗口映射、rate 切换限制、循环片段 | 官方客户端对照，分数/窗口差异记录 |
| 失焦/睡眠 | context 暂停、tab 切换、清空按键状态、恢复策略 | 后台程序负载、设备切换、显示器刷新率 |

浏览器必须有用户手势初始化音频。测试时记录 AudioContext sampleRate、可用 latency 信息、DSP 延迟和 underrun 指标。浏览器内部 timing 正确不等于硬件“按键到出声”延迟已验证。

正式支持环境先固定 Windows + Chrome/Edge 的具体版本，其他浏览器按兼容结果标记。自动化中无真实输出设备的测试不宣称测得硬件延迟。

## 5. 性能基准与目标

以下为初始目标，M0 固定参考机和基准后可以调整；调整须记录原因与测量。每次报告列出 CPU、内存、磁盘、浏览器、屏幕分辨率、刷新率、冷/热缓存和后台任务。

| 指标 | 初始目标 | 测量方式/限制 |
| --- | --- | --- |
| 普通放键内核处理 | p95 ≤ 4 ms | 编辑内存状态，不包括设备输入、屏幕扫描和持久化 |
| 60 Hz 连续编辑帧 | p95 ≤ 16.7 ms | 固定 1080p 基准，100k 音符；记录可视对象数与 LN 密度 |
| 高刷新率 | 144 Hz 单独测量 | 目标匹配约 6.9 ms 帧预算；未通过不声称支持同等效果 |
| 可见多轨道 | 8 条轨道压力样本可交互 | 若必要采用 LOD；记录合计音符数、visible 数和同步方式 |
| 持久化确认 | 正常 SSD p95 ≤ 250 ms | 从提交到对应日志刷盘确认；不通过则明确显示待持久化 |
| 热索引搜索/过滤 | p95 ≤ 200 ms 返回首屏 | 50k mapset/200k difficulty；包含短中文词、标签组合和排序 |
| 曲库滚动 | 与 60 Hz 帧预算相同 | 虚拟列表与封面惰性加载；不能靠加载全部数据获得热缓存成绩 |
| 暖音频 seek | 普通路径 p95 ≤ 150 ms；保音高路径 p95 ≤ 300 ms | 含 DSP 重置/预热；极端倍率单列实测限制 |
| 相对时钟漂移 | 常规倍率 5 分钟内 ≤ 5 ms | 测 transport 映射及算法延迟补偿，不是跨设备绝对延迟保证 |
| 批量粘贴 | 10k 音符完成 ≤ 1 s，可显示进度 | 单次提交；期间不能长时间冻结 UI 或产生半提交 |
| 难度候选预览 | 代表样本暖缓存 p95 ≤ 200 ms | 近似与精确分别报告；全谱精确计算异步且可取消 |
| 混合负载 | 播放编辑期间无持续 >100 ms UI 卡顿 | 同时进行扫描/频谱/难度任务，重点检查任务限流 |

上述性能目标不是安全约束的替代：不能为了确认 ≤250 ms 而在 flush 前确认，也不能为了 seek 速度错误对齐歌曲位置。

首次全库扫描时间受文件数量、目录布局、磁盘和冷缓存影响，不先承诺固定秒数。报告吞吐、首屏可用时间、UI 响应、内存峰值、I/O 和增量重启耗时。未改动启动不能完整解析所有音符或解码全库音频。

压力数据至少包括：

- 小谱面：约 2k 音符，密集 RC、混合 LN、多个 timing 段。
- 大谱面：100k 音符；超长 LN、密集同刻事件与大量 SV。
- 多轨道：8 条可见轨道、独立/同步滚动、多歌曲对照。
- 大库：50k mapset / 200k `.osu`，中文/日文路径、同名文件、缺失资源。
- 长音频：30 分钟以上文件，验证内存策略；按 PCM 实际大小核算，不按压缩文件大小。

缓存和音频内存采用可配置预算及 LRU；M0 实测后确定发布默认值。所有资料遍历均可分批与取消，不能依赖用户每次等待完整扫描。

## 6. 自动分析验收

BPM/offset 使用合成音频的已知 BPM/offset/变化点、0.5x/2x 等价节奏、切分、弱起、休止和连续变速测试。结果必须包含候选、置信度和区间，不以全曲平均 BPM 冒充变速识别。

难度使用锁定的官方与 Sunny 实现作为 oracle，并记录 commit、rate、列数和预处理选项。代表 RC/LN/混合/变速/极密样本覆盖 7K，不因 4K 样本通过就宣称适合 7K。

数值容差依据 oracle 的精度与实现制定，单独比较整体结果、局部曲线和排序稳定性。针对同刻和弦重新排列输入，检查计算顺序是否产生意外变化。存在已知上游行为时文档化，不偷偷“修复”成另一套算法。

假设预览检查：不会实际修改谱面、可取消、旧 revision 结果被丢弃、精确/近似标识正确。若声称增量结果精确，必须与全量重算比对；Sunny 等全谱依赖不能只截一个短窗口就宣称等价。

## 7. 检查、构建和回归分层

- 每个变更：对应的领域/协议/集成测试、Python lint/类型检查、TypeScript 类型检查及前端构建。
- 文件/恢复变更：故障注入和项目升级测试；音频/输入变更：对应浏览器端到端测试。
- 阶段交付：完整适用测试、端到端主要工作流、固定性能样本及可运行包验证。
- 正式发布：干净机器启动/退出、无需开发环境、安装/便携包路径、版本升级、资源和许可证清单、兼容矩阵。

检查发现新问题后追加具有复现价值的回归测试；检查已经通过且代码没变化时不反复扩大测试范围拖延交付。测试报告列出实际执行的命令、环境和结果，未执行的项目保持待验收。

## 8. 用户真实测试的简短流程

M2 首次试用：复制一首真实歌曲建立项目 → 确认 BPM/offset → 写一段 7K tap/LN → 复制/变换与撤销 → 播放/简单试玩 → 保存 → 在 osu! 打开 → 退出重开检查完整性。

后续阶段分别补充：自定义 hitsound/LN 与 rate、真实大 Songs 库、双向复制迁移、中心对车与排列文本、历史恢复与皮肤、变速 BPM 和难度局部预览。

用户不必编写测试；遇到问题时提供复现操作、样本副本或时间点，Codex 负责诊断、修复和验证。计划内的真实测试先以副本进行，待相应可靠性验收通过后再开放原位 Songs 工作流。
