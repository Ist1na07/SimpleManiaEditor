# 曲库整理、迁移与版本历史（0.1.31）

## 写图时的操作流

点击左上角品牌回到曲库。把 osu! 的 Songs 添加为只读目录，把自己的作品保存在创作目录。双击难度进入编辑；原件在创作目录外时，沿用独立副本工作流。普通编辑、保存和版本记录不会写 Songs。

看到值得研究的排列，在难度行点「整理 / 迁移」，勾选收藏、添加 `排列参考, LN` 标签，并写下“第二段的交互适合参考”。自己的待发布图可设为「未发布」。这些信息在难度行和歌曲卡片中显示，不进入 .osu。选择多个歌曲卡片后使用顶部「批量整理」，只修改当前搜索结果中选中卡片的可见难度；备注保持原样。批量标签支持添加和移除。

顶部「★ 收藏」「未发布」可直接进入常用筛选。搜索支持空格组合、引号短语和 `-` 排除，例如：

```text
tag:LN star:true keys:7
state:未发布 creator:Ist1na
note:第二段 -tag:已参考
"排列参考" -state:已发布
```

普通文字匹配曲名、歌手、作者、难度、路径、标签、备注和状态。`keys:7k` 也有效。中文一两个字可以搜；这类短词需要扫描索引，通常比长词慢。搜索有短暂输入合并，在后台执行，过期结果不会替换新查询。

## 整套谱面往返

1. 保存相关编辑，退出 osu!。从难度行的「整理 / 迁移」打开「复制 / 迁移整套谱面」。
2. 选择目标曲库根目录，如 Songs 或自己的创作目录。默认是**复制**，源文件保持存在。只有勾选迁移才会在校验成功后移走源文件。
3. 生成预览，检查源、目标、全部文件和体积。重名会生成带编号的新文件夹，绝不合并覆盖。
4. 勾选核对确认，再执行。完成后目标根目录加入曲库，相关个人整理信息和版本身份沿用。
5. 需要撤回时打开曲库顶部「迁移记录」，选择对应事务并确认回退。

迁移单位是整个歌曲文件夹，包括其他难度、音乐、背景、视频、故事板和子目录资源。禁止把整个曲库根目录当歌曲迁移；拒绝目录链接和内嵌 .git。执行涉及 Songs 的事务时若 osu! 正在运行，会停止并提示退出。

实现顺序是临时目录复制、逐文件 SHA256 核对、持久化事务记录、发布新目录、可选清理源文件。实际移动会额外保存完整源副本。准备阶段可以取消；发布后先完成事务。中断后在「迁移记录」回退；下次刷新曲库也会提示未完成事务。目标或源位置出现新编辑时，自动回退会停止，不会抹掉新内容。关闭正在恢复的窗口会被阻止。

迁移回退副本不会自动删除，目前没有备份清理界面。它们可能较大，应将应用数据目录一并纳入备份计划。测试覆盖软件故障注入和重启后恢复，不代表已完成真实断电或所有文件系统的验收。

## 测图前留版本，修改后对照

顶部「版本历史」与普通保存分开。打开谱面时尝试记录起点；首次保存前保留磁盘旧稿；后续成功保存后自动记录内容不同的快照。打开历史面板可填写“第二段改 LN，准备 0.75x 测图”等说明，创建命名版本。内容相同不会重复创建提交。

左侧始终展示历史列表；右侧默认是当前编辑内容（包括未保存修改），也能选另一历史版本。红色代表从所选历史到比较版本被移除的音符，绿色代表新增，灰色代表位置和长度相同。Tap/LN 都使用共同的歌曲毫秒轴，因此 Timing 改动导致的音符时间变化也可见。通过时间滑条和 1 秒 / 5 秒 / 10 秒 / 全曲范围查看；点击音符差异行可定位。下方列出 Timing 和谱面属性变化。

恢复前先勾选确认。恢复会先记录当前稿，再将旧稿作为一次可撤销编辑应用；Ctrl+Z 可以返回，按保存才写回文件。历史不会被 reset。需要取回旧音乐或背景时，使用「另存左侧版本及资源」，选择父目录，程序新建独立文件夹。恢复编辑内容不会直接覆盖当前资源。

命名版本默认包含资源；自动保存版本沿用上一次记录的资源。更换音乐、背景后请创建包含资源的版本。资源按 Git 对象去重。当前资源变化列表表示所选版本相对其父版本的变化，不是任意两版资源比较。导出的是当前这张难度及记录的资源，其他 .osu 难度不包含在它的版本仓库里；整个 mapset 的搬迁请使用迁移功能。

## 数据位置与边界

- 索引和整理信息：应用数据目录的 `mapper-library.sqlite3`，使用 SQLite WAL；索引可重建，个人身份和注释独立保存。
- 可读个人信息备份：同目录 `library-personal.json`，修改整理信息或关联迁移身份后原子替换。新建数据库时若该文件存在，会恢复这些身份和注释；当前没有自动修复损坏数据库的界面。
- 版本：`Versions/<谱面身份>.git`，真实裸 Git 仓库，程序自带 libgit2，不需安装 Git，也不会推送用户作品。
- 迁移：`Transfers/` 中的 JSON 事务记录与源文件备份。

分发入口的应用数据默认在 `%LOCALAPPDATA%\SimpleManiaEditor\Distribution`；开发体验入口可能使用 Preview。创作文件仍在自己选择的目录。备份时应保留作品目录与整个应用数据目录，仅复制 .osu 不包含备注或历史。

目前使用文档快照，并未把每次鼠标编辑持久化成 command journal；分支、合并、远程 Git 和合作编辑尚未提供。音符位置/LN 长度有可视化 diff，音效属性、草稿及任意原始字段的完整语义 diff 仍需补齐。版本面板目前最多列出最近 1000 个提交。

## 本轮性能记录

隔离生成素材，本机 Release 构建，未扫描或修改用户真实歌曲库：

| 工作负载 | 结果 |
| --- | --- |
| 20 万条合成元数据首次建索引 | 62.3 秒，数据库约 287 MiB |
| 20 万条重新读取缓存头部 | 2.91 秒，启动时放在后台 |
| `Albemuth keys:7`，5129 条结果 | 69.5 ms |
| `Song 19999`，16 条结果 | 15.1 ms |
| `creator:Mapper`，20 万条结果 | 1408.7 ms |
| `keys:7 -Albemuth`，61538 条结果 | 667.3 ms |
| 5 万个实际生成的 .osu 文件首次扫描并持久化 | 21.66 秒 |
| 相同 5 万文件缓存已载入后的扫描 | 2.16 秒，头部解析 0 次 |

首次索引需要枚举目录和读取谱面头部；不解码音乐或载入完整 HitObjects。缓存按大小和修改时间失效，文件监听合并变化后更新。宽泛查询仍有百毫秒到秒级耗时，后台搜索不能等同于所有查询都瞬时完成；磁盘、杀毒软件、网络盘和真实素材会影响结果。
