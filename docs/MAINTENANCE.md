# 本地清理与 osu! 隔离检查

日常改动只构建本地体验版。只有用户明确要求发布时，才创建 GitHub Release、发布标签或上传分发包。

## 清理

关闭编辑器／试玩后，双击仓库根目录 Clean-LocalBuilds.cmd。开发环境需要 PowerShell 7、Python 3.12+ 和 Git。

清理工具每次重新读取当前文件状态，不再复用上一次构建前的旧计划。它会从启动脚本识别当前编辑器和演示版本，保留对应运行目录，并保留最近公开的分发版作为回退副本；保留源码、Git 资料、谱面、音乐、皮肤、备注、设置、历史与备份。旧压缩包中的非程序文件会先核对已有副本，独有内容保留在 artifacts/retained-archive-data。

删除前检查目标绝对路径、目录链接、Git 跟踪状态、文件长度与时间。仅逐个删除清单中可重建的生成文件，不递归删除整个旧版本目录。清理前后还会校验保留文件的 SHA256。结果在 artifacts/cleanup-result.json。

预览可运行 scripts/Clean-LocalBuilds.ps1 -Preview，只生成当前计划，不删除生成文件。预览和正式执行之间如果又构建过，正式执行会重新盘点；执行过程中变化的文件会停止处理或跳过。

2026-10-15 的实际清理：删除 47,005 个生成文件，释放 43,725,817,834 字节（约 40.72 GiB），13,915 个保留文件校验通过，失败数 0。没有清理真实 osu! 安装目录。

完成本地修订和验证后，又清理本轮产生的 2,106 个中间文件／重复构建，释放约 1.37 GiB，保留文件再次校验通过。两轮合计约 42.09 GiB；交付时 E 盘可用约 42.85 GiB。

## 试玩目录限制

试玩现在使用固定的编辑器数据目录，不再使用官方独立客户端可迁移的 OsuStorage。已有 storage.ini 的 FullPath 不会改变试玩目录，也不会被静默改写。原皮肤、键位、音频与游戏设置仍使用官方组件；仅屏蔽独立客户端的「更改游戏文件夹」入口。

试玩文件访问会检查物理路径，阻止绝对路径、上级目录和目录链接跳出自己的数据目录。测试覆盖带有跳转配置的假客户端目录、绝对路径／移动／删除／目录链接操作，外部文件保持原样。

这是确认存在的隔离风险修补，**尚未确认是用户报告的 stable 修复提示的根因**。

## 当前调查结果

2026-10-15 检查真实 stable 目录：

- 最新更新日志记录 No changes to apply、NoUpdate，没有说明哪个文件损坏。
- 在完整编辑器启动／预热／退出，以及使用用户原皮肤的官方 GPU 试玩前后，对 190 个程序、配置、数据库与所用皮肤文件比较大小、SHA256、修改时间和属性；没有变化。
- 同时监听真实安装目录及所有子目录的创建、修改、删除、重命名、属性和权限事件；该次测试为 0 条变化，未出现监听溢出。
- 未启动原版 osu!，未自动修复或重置原版客户端、数据库、权限或文件关联。

这些结果只能说明本次操作未观察到写入，不能证明所有真实使用路径都没有问题，也不能把修复提示标记为已解决。具体提示原文与稳定复现步骤仍待确认。

开发者可使用 scripts/Check-OsuIsolation.ps1 -OsuRoot '<真实安装目录>' 重复检查；它会短暂启动测试窗口，使用独立临时编辑器资料和合成音乐／谱面，读取当前选中的原皮肤，不改现有编辑会话。私有报告与截图保存在输出所示的临时目录，不上传。

## 本地构建

scripts/Build-Local.ps1 -Dotnet '<SDK 的 dotnet.exe>' 会构建到新的本地目录，运行编辑器和试玩存储检查，成功后更新 Start-Editor.cmd。不创建 ZIP、不打标签、不发布 Release。不会覆盖已有运行目录或作品。
